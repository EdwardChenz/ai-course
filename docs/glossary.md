# 术语表

本书共 290 条术语，按字音与字形顺序（忽略大小写）排列。

每条包含定义、在本书中的意义，以及一个来自本书语境的例子。
需要深入了解某个概念时，可回到对应章节；每章首页都列出了该章覆盖的概念及其重要度。

#### A2A横向互联观

把 A2A 理解为 Agent 之间的对等协作通道，解决"谁能和谁一起做事"。

它管的是 Agent 到 Agent 这一横，与向下的工具接入方向相反，见 MCP纵向工具观。

**Example:** 把内部排期 Agent 对接外部公司的审批 Agent，双方互不暴露内部工具。

#### Agentic编码总览

让编码 Agent 承担实现、测试与修复的协作工作方式。

它正在实质改变软件开发的分工方式。

**Example:** 把需求写成可验证的规格交给 Agent，人负责评审与合并。

#### Agent身份标识

为每个 Agent 分配可验证的身份标识与归属信息。

它是权限控制、审计追溯与计费归属的前提。

**Example:** 签发含主体、角色与作用域的令牌，日志里可反查是谁发起的调用。

#### AutoGen框架入门

用可对话的 Agent 实例与消息驱动方式搭建多 Agent 应用。

它是理解各类协作模式最直接的代码参考。

**Example:** 会话型 Agent 关闭人工输入后，两个角色可自动对答完成任务。

#### Cypher查询入门

用类 SQL 的模式匹配语法在图数据库中检索节点与关系。

不掌握 Cypher 就只能写死路径，图的价值无法发挥。

**Example:** `MATCH (a:Company)-[:CONTROLS]->(b) RETURN b` 找出一层控股关系。

#### Dagster资产管理

以数据资产为中心定义表、依赖与校验，并调度其物化。

它面向数据资产编排，与运行时流程编排关注点不同。

**Example:** 把日活宽表定义为资产，声明依赖上游原始表并配置调度规则。

#### Daytona优先实践

在多方案中优先采用 Daytona 建立沙箱基线，再评估替代方案。

先跑通一条基线，避免把时间耗在选型上。

**Example:** 先验证启动耗时与并发上限，再评估是否有必要更换方案。

#### Daytona沙箱部署

用托管沙箱服务提供按需创建的执行环境与快照能力。

它省去了自建隔离环境的运维负担。

**Example:** 每次代码执行请求创建一个独立沙箱，用完即销毁并回收资源。

#### DeepEval优先实践

优先用 DeepEval 落地断言式评测，再考虑更重的方案。

先把评测跑起来比选型完美更重要。

**Example:** 先覆盖十条关键用例，形成每次改动必跑的质量红线。

#### DeepEval评测接入

用开源评测库定义断言与数据集，批量计算指标。

它把主观判断固化成可复跑的自动化断言。

**Example:** 为每条用例写"必须引用给定政策条款"的断言，批量执行得到通过率。

#### Docker卷与网络

用命名卷持久化容器数据，用自定义桥接网络实现容器间的服务名互访。

向量库数据与沙箱产物都需要跨容器重启保留，网络则支撑多容器拆分。

**Example:** 向量库挂命名卷，网关与 API 服务加入同一网络后直接用服务名互访。

#### Docker环境变量配置

通过 `-e` 或 env_file 把密钥与开关注入容器，避免写进镜像层。

镜像会在多环境复用，配置外置才能避免为每个环境重新构建。

**Example:** `docker run -e OPENAI_API_KEY=$KEY app:1.2`，密钥不会出现在 `docker history` 中。

#### Docker镜像构建

用 Dockerfile 描述基础镜像、依赖与启动命令，`docker build` 生成分层镜像。

模型与 Agent 的依赖树复杂，需要可复现的运行载体。

**Example:** 基于 `python:3.11-slim` 分层 `pip install`，配合缓存挂载缩短构建时间。

#### E2B对照实践

以另一家沙箱服务做同口径对比，验证是否值得切换方案。

没有对照就容易因单点问题误判整个方案。

**Example:** 用同一份代码对比启动时延、并发上限与单次执行成本。

#### Ecc工程实践

把工程规范、目录约定与自动化检查固化为项目基线。

规范若不落成可执行检查，就只能靠人记。

**Example:** 把 lint、类型检查与依赖审计接进提交前钩子。

#### Embedding模型选型

按领域、语言与维度选择把文本映射为稠密向量的模型。

更换嵌入模型等于重建全库索引，这个决策必须尽早做定。

**Example:** 中文知识库选 bge-m3，维度 1024，写库前先锁定模型版本。

#### FastAPI流式响应

用 `StreamingResponse` 以 SSE 分块把增量结果推给客户端。

Agent 任务耗时较长，需要边生成边返回才能压住首字延迟。

**Example:** 把链的 `astream` 逐块 yield 成 `data: {...}\n\n`，前端即时渲染。

#### FastAPI路由与校验

用路径操作声明接口，由 Pydantic 对入参与出参做类型校验并生成文档。

它是把 Agent 能力暴露为 HTTP 接口时的第一道契约防线。

**Example:** 定义 `QueryRequest` 模型，`@app.post("/search")` 收到非法 query 直接返回 422。

#### FastMCP服务搭建

用装饰器把 Python 函数注册成可被发现和调用的 MCP 工具。

它显著降低自建 MCP 服务的接入与协议适配成本。

**Example:** 用 `@mcp.tool()` 标注查询函数，服务启动后客户端即可列出并调用。

#### ffmpeg合成链

用命令行工具完成切片、拼接、转码与字幕烧录。

剪辑环节决定成片规范与最终播放兼容性。

**Example:** 按清单拼接分段并压到指定分辨率，批量处理整批素材。

#### Git分支协作流程

用 main、develop、feature 分支与 PR 评审组织多人并行开发。

Prompt 与参数实验分支众多，合并冲突会污染评测结果的可比性。

**Example:** 每个 Prompt 实验开一个 feature 分支，评测通过才发起 PR 合回主干。

#### Herd协作思路

让一群同构 Agent 独立作答，再由投票或打分选出最优。

它适合有明确评价标准的任务，答案多样性带来收益。

**Example:** 三个 Agent 独立生成候选答案，用评测器打分取最高分。

#### HTTP流式传输

用分块编码或 SSE 边生成边推送，服务端不必缓存完整响应即可交付。

它降低首 token 延迟，也是实现可打断交互的前提。

**Example:** 用分块传输逐段吐出文本，客户端收到第一段就开始渲染。

#### Iceberg表格式

提供快照、增量读取与模式演进能力的开放表格式。

它让数据湖具备事务语义，支持可靠的分区级更新。

**Example:** 按日期分区更新时只重写受影响的分区文件。

#### JSON Schema校验

用结构定义描述字段类型、必填项与取值范围，并在运行时校验数据形状。

模型输出与工具入参都不可信，缺少校验等于把脏数据写进系统。

**Example:** 设置 `additionalProperties: false` 挡掉模型多编出来的字段。

#### LangChain Agent互联

把基于 LangChain 构建的 Agent 包装成可被外部调用的端点。

存量 LangChain 应用接入互联体系时需要一层适配。

**Example:** 把已有的链包成符合跨框架消息格式的服务端点。

#### LangChain记忆组件

框架提供的会话缓冲、摘要与外部存储实现，用来在链之间传递历史。

它是对话历史管理的一种现成实现，不等于完整的记忆层设计。

**Example:** `ConversationBufferMemory` 直接保存原始消息，长会话改用摘要型实现。

#### LangChain链式编排

用 LCEL 把提示、模型与解析器组合成声明式的处理流水线。

它把一个巨大的提示拆成可单独替换与测试的步骤。

**Example:** `prompt | llm | parser` 定义问答链，换模型只需改中间那一环。

#### LangFuse优先实践

先以 LangFuse 建立统一的观测基线，再叠加其他平台。

观测方案越早统一，后续接入成本越低。

**Example:** 所有服务统一标签体系，避免各项目自定义字段导致无法聚合。

#### LangFuse追踪接入

采集链路、提示词与评测数据的可观测平台，可自托管或托管。

它是排查模型调用问题的通用底座。

**Example:** 在入口注入追踪上下文，把每步提示、响应与耗时写入平台。

#### LangSmith对照实践

与商业托管追踪平台做同口径比较后决定取舍。

需权衡数据出境、费用与自持可控性。

**Example:** 对比自托管的算力成本与托管报价在同量级用量下的费用。

#### Linux日志排查

用 journalctl、grep、tail 在服务器上按关键字与时间窗定位异常。

线上问题的证据只在服务器上，取证能力决定定位速度。

**Example:** `journalctl -u api --since "10 min ago" | grep -i timeout` 捞出超时请求。

#### LiteLLM网关配置

用统一网关统一不同模型提供方的调用、鉴权与统计。

多模型并存时，避免在业务代码里维护多套客户端。

**Example:** 在网关配置多个模型别名并统一主密钥，业务侧只认别名。

#### Mattpocock工作流

以规格、纯函数设计与人工把关来组织开发过程的方式。

它提供了一套可复制的协作节奏。

**Example:** 把接口定义与纯函数实现分开，Agent 每次只做一类改动。

#### MCP与A2A互补模型

用纵向取能力、横向做协作的组合来划分系统边界。

边界清晰才能判断该自建工具层，还是只做互联一侧。

**Example:** 自家 Agent 用 MCP 接工具，需要外部伙伴协作时才引入 A2A。

#### MCP与函数调用对比

对比两者的调用入口、能力发现范围与部署形态的差异。

MCP 不是函数调用的替代，而是它面向跨进程的扩展形态。

**Example:** 函数调用把工具写在同一进程内，MCP 让工具独立部署并被多个客户端共享。

#### MCP协议总览

约定 AI 应用与外部能力提供方之间的通信规范，含工具、资源与提示三类接口。

它把工具接入从一次性编码变成可复用的标准契约。

**Example:** 客户端发现服务端能力后调用工具执行接口，无需了解工具内部实现。

#### MCP客户端集成

在应用中配置客户端连接服务端，并管理会话与连接复用。

连接复用与超时设置直接影响整体调用延迟。

**Example:** 用会话池复用标准输入输出连接，避免每次调用都重启子进程。

#### MCP纵向工具观

把 MCP 理解为 Agent 向下的能力获取通道，解决"我的 Agent 能做什么"。

它管的是 Agent 到工具这一纵，与 Agent 之间的横向互联互补，见 A2A横向互联观。

**Example:** 把公司内部订单查询服务包成一个 MCP 服务器，供多个 Agent 复用。

#### Mem0记忆层总览

独立的记忆中间层，自动抽取、存储并检索用户与场景记忆。

它把记忆能力从业务代码中解耦，便于替换与审计。

**Example:** 每轮对话交给该层写入，检索时只取与当前意图相关的记忆。

#### Minimax H3生成

通过另一家视频生成服务接口产出短视频画面素材。

不同服务在风格与成本上差异明显，需要对比后选型。

**Example:** 同一分镜在两家服务各生成一版，比较风格一致性与单价。

#### Neo4j部署与驱动

以容器或集群方式运行 Neo4j，并用官方驱动读写图数据。

它是 GraphRAG 落地中最常见的技术栈底座。

**Example:** 启动 `neo4j:5` 容器后，用 `GraphDatabase.driver` 注入并获取会话。

#### Office CLI提效

按平台与业务线等维度为每类内容记录它实际消耗的算力与费用明细。

报告与表格的生成可以全流程脚本化。

**Example:** 脚本填充模板生成周报，并把结果写回云端文档。

#### OpenAI Agent SDK

提供工具调用、任务交接与链路追踪能力的 Agent 开发框架。

它适合在托管模型上快速验证协作模式。

**Example:** 用其交接机制把检索任务转给子 Agent，同时复用平台追踪能力。

#### ORCA开发范式

强调规格先行、以可验证的验收标准驱动开发过程的协作方式。

它把"写代码"变成"满足一份可验证的规格"。

**Example:** 先写清输入输出与边界条件，再让编码 Agent 实现并自测通过。

#### Polaris数据湖搭建

用开源目录管理数据湖中的表、权限与版本。

跨引擎共享同一套数据目录，避免重复建表。

**Example:** 各计算引擎统一从该目录解析表路径并读取授权。

#### Ponytail协作模式

强调最小必要上下文与短反馈回路的一种协作方式。

上下文越干净，Agent 越不容易偏离任务本身。

**Example:** 每次只把相关文件与验收标准放进上下文。

#### Python异步编程基础

用协程与事件循环在单线程内并发等待 I/O，无需多线程即可提升并发能力。

大模型调用属于网络等待密集型操作，并发写法直接决定单实例能承载多少请求。

**Example:** 一个 RAG 服务用 `asyncio.gather` 并发跑八路召回，把端到端延迟从 800ms 压到 200ms。

#### Python虚拟环境管理

用独立目录隔离解释器与依赖版本，使不同项目各自锁定一套库。

环境隔离是模型客户端库频繁升级时的基本保障，冲突会直接让服务起不来。

**Example:** 用 `uv venv` 建目录，再 `uv pip freeze` 导出锁定文件，CI 与本地装出一致的依赖。

#### RAGAS对照实践

用另一套 RAG 指标的忠实度与相关性做横向对照。

不同指标口径不同，同一系统的数值不可直接比较。

**Example:** 同一批用例下对比两个指标，看哪个与人工判断更一致。

#### RagFlow流水线部署

部署开源 RAG 平台，用可视化节点拼装解析、索引与检索流程。

适合快速验证复杂文档解析，但不是定制架构的终点。

**Example:** `docker compose up` 拉起服务，导入 PDF 后配置分块与索引节点。

#### RAG上线清单

上线前逐项核对数据、检索、生成、监控与回退准备。

它把个人经验变成可复用的发布流程，减少遗漏。

**Example:** 清单包含索引版本号、评测分数、引用率阈值、降级开关与回滚步骤。

#### Realtime语音架构

以流式识别、模型推理与流式合成分段串联的低延迟语音链路。

延迟由每段累加决定，必须分段优化而非整体优化。

**Example:** 识别、思考与合成三段并行流水，首句响应压到八百毫秒内。

#### RunningHub云任务

用云端工作流平台编排并执行多步骤生成任务。

它把生成、增强与合成串成一条可重跑的链。

**Example:** 定义文生图、视频化、转场与拼接节点，云端排队执行并回收产物。

#### Seedance视频生成

用视频生成模型产出短视频素材的接口与调用流程。

短视频生产中，生成环节占主要成本与工期。

**Example:** 提交分镜描述与时长后拿到任务标识，轮询进度并取回成片。

#### Shell脚本自动化

用 Bash 把重复的构建、发布、备份步骤固化成可重复执行的脚本。

脚本化能消除手工发布的偶然性，让失败点明确可查。

**Example:** `deploy.sh` 依次执行构建、拉镜像、切流与健康检查，任一步失败即退出。

#### Skill机制设计

把可复用的操作封装成可被 Agent 触发的技能包。

它让一次性提示变成可长期积累的能力。

**Example:** 定义技能描述、参数与示例，命中时自动装载对应说明。

#### Supabase项目搭建

用托管后端服务组合数据库、认证、存储与实时能力。

它适合快速为 Agent 应用补齐账号体系与数据层。

**Example:** 创建项目拿到连接串与匿名密钥，前端直接订阅数据变更。

#### Superpowers实践

通过明确的技能定义与流程约束提升编码 Agent 的产出质量。

约束越明确，Agent 的自由发挥空间越小、结果越可控。

**Example:** 强制先写测试再改实现，Agent 给出失败用例后才被接受。

#### Temporal优先实践

运行时编排优先采用 Temporal，把易失状态收敛进工作流内部。

优先用框架解决持久化，而不是自己手写状态机。

**Example:** 所有等待都用可持久化的定时器，不依赖进程内存。

#### Temporal编排入门

用工作流与活动两类单元表达长时间、可恢复的执行流程。

它为运行时编排提供状态持久化与失败恢复能力。

**Example:** 把调模型、调工具、写结果定义为活动，串成可重放的工作流。

#### Token与上下文窗口

用 token 数衡量文本长度，模型单次可处理的 token 上限即上下文窗口。

它同时决定能塞多少历史与资料，以及单次调用的费用量级。

**Example:** 8K token 文档加 2K 对话历史与 500 输出，正好触到 12K 窗口上限。

#### Token成本归因

把 token 开销拆解到模型、环节、用户与场景四个维度。

只算平均成本看不出问题究竟出在哪里。

**Example:** 统计显示大部分成本来自重排序环节，调整候选数后明显下降。

#### TopK召回调参

检索阶段捞入候选集的条数，及其在召回充分性与上下文成本间的权衡。

取值偏小会漏掉关键片段，偏大则把噪声塞进上下文并抬高费用。

**Example:** TopK 从 5 提到 20 后召回率上升，重排得分 0.4 分以上的片段从两条增至七条。

#### Trace根因定位

沿链路追踪数据自顶向下逐层缩小问题所在的环节。

Agent 的失败往往在某一层输入时就已埋下。

**Example:** 答案异常时先看召回片段，发现提示里被填成了上一轮的用户问题。

#### Trino分布式查询

用跨源联邦查询引擎直接查询多个数据源而不搬迁数据。

Agent 临时取数时，落仓的成本太高。

**Example:** 一条 SQL 同时查询湖中的事实表与库中的维表。

#### vLLM部署入门

用高性能推理引擎以兼容接口部署开源模型。

它是自建推理以控制成本与避免数据出域的主流选择。

**Example:** 命令行启动后可直接用 OpenAI SDK 调用。

#### 一对一辅导规划

安排周期内的辅导主题、材料与每次的验收任务。

短期突击同样需要明确节奏与产出。

**Example:** 每周一个主题，末尾提交一个可运行的最小项目。

#### 上下文压缩

从召回片段中抽取与问题相关的句子，去掉冗余与重复内容。

窗口有限，尽量把预算留给有效证据而不是背景铺垫。

**Example:** 给每个片段打分后只保留前两句，总长控制在 1500 字以内。

#### 上线质量门禁

用预设阈值判定某次变更是否允许进入线上环境。

它把发布决策从主观判断变成明确规则。

**Example:** 忠实度低于阈值或引用率过低即阻断发布并说明原因。

#### 业务审计日志

记录谁在何时对什么数据做了什么操作，且内容不可篡改。

它既是合规要求，也是问题发生后定位责任的唯一依据。

**Example:** 写入独立审计表并禁止业务账号删除，同时保留操作前后值。

#### 中级RAG全流程

从加载切分、向量化入库到召回重排、拼装提示、生成回答的完整链路。

它是后续所有变体与优化手段共同的对照基线。

**Example:** 面试中要能按顺序讲清这六步，并指出每一步的典型失败点。

#### 互联上线清单

上线前核对身份、限流、回执、监控与应急联系人。

互联故障影响面大，必须事先准备明确的处置预案。

**Example:** 清单包含令牌轮换方案、超时阈值、失败回执约定与对账方式。

#### 互联故障排查

沿调用链定位超时、格式不符或鉴权失败等互联问题。

跨进程问题缺乏调用堆栈，只能靠日志与链路记录还原。

**Example:** 委托返回空结果，逐段比对后定位到工具调用字段名不一致。

#### 人机协同节点

在流程中设置由人确认或补充信息的关键断点。

把人的判断放在高价值与高风险处，而不是全程盯守。

**Example:** 对外发送邮件前必须人工确认，之前的步骤全自动执行。

#### 从Demo到服务封装

给实验链路补上接口、鉴权、配置、超时、监控与错误处理，使其可上线。

这一步决定方案能否进生产，而不是停留在笔记本里。

**Example:** 把链包成 FastAPI 服务，加限流、结构化日志与健康检查。

#### 代理执行循环

反复执行"模型思考—工具调用—结果回填"直到得出终态答案的迭代过程。

它决定 Agent 能否完成任务，也决定 token 上限与失控风险。

**Example:** 设最大八轮迭代，超限则返回中间结论并说明未完成的部分。

#### 代码执行审计

记录每次执行的代码、输入输出与资源占用以备追溯。

执行任意代码的场景必须有完整的取证能力。

**Example:** 把执行日志与最终产物关联存储，保留可复现所需的全部环境信息。

#### 代码执行工具

在受控环境中执行模型生成的代码并返回运行结果。

它把生成能力从"能写代码"变成"能真正跑通"。

**Example:** 执行前做语法与依赖白名单校验，并限制输出行数与运行时长。

#### 代码评审实战

让 Agent 承担初筛与规范检查，最终判断仍由人做出。

它能滤掉大量低级问题，但结论仍需人工确认。

**Example:** 评审 Agent 只输出能定位到具体行的清单与复现步骤。

#### 任务交接协议

定义 Agent 之间传递任务与上下文的消息结构与字段约定。

交接信息不足，后续接手者只能靠猜。

**Example:** 交接消息包含目标、已得证据、约束条件与已排除方向。

#### 任务分解策略

把复杂目标拆成可独立执行且可验证的子任务。

拆得不可验证，出错时无法定位到具体是哪一步。

**Example:** 把"写一份竞品分析"拆成资料收集、维度对比、结论成文，每步设完成判据。

#### 任务委托协议

约定任务下发、回执与部分失败时的通信格式。

跨组织协作无法靠修改代码来协调，必须有书面约定。

**Example:** 接收方必须回执已接收或已拒绝及原因，避免单方无限等待。

#### 任务状态同步

让委托方持续获知任务进展、阻塞情况与最终结果。

状态不可见会让调用方只能盲等或重复下发。

**Example:** 提供任务状态查询接口，双方轮询或订阅状态变更事件。

#### 任务状态机

用显式状态与合法转移规则描述任务的生命周期。

它让重试、超时与取消有明确依据，避免状态不一致。

**Example:** 状态含待执行、执行中、待审批、成功与失败，非法转移直接拒绝。

#### 企业文档问答实战

面向内部制度与手册构建问答能力，需处理多版本文档与权限差异。

难点主要在版本治理与权限隔离，而不在检索算法本身。

**Example:** 制度库按生效日期保留多版本，检索时先按时间过滤再作答并标注版本号。

#### 会话持久化

把会话与消息写入数据库，使其跨重启与多实例共享。

纯内存态会话在实例重启或扩容后会丢失。

**Example:** 每轮消息落库并关联会话标识，新实例按标识恢复上下文。

#### 会话迁移机制

在会话中断后把上下文与状态转移到另一个执行点继续执行。

长任务换实例或跨组织转交时，不能从头再来。

**Example:** 把会话状态序列化后在新会话恢复，续接未完成的委托任务。

#### 作品集讲述稿

准备用固定结构讲清项目背景、方案、取舍与成果的讲稿。

面试中讲不清取舍，项目亮点就无从体现。

**Example:** 讲稿按背景、难点、方案、指标提升、个人贡献五段组织。

#### 供应链图谱实战

用图表达供应商、零部件与工厂之间的层级依赖关系。

影响分析需要跨多层的路径查询，文本检索难以支撑。

**Example:** 某芯片缺货时，用两跳查询列出全部受影响的整车厂。

#### 依赖锁定与复现

锁定精确版本与校验哈希，保证任意机器能装出同一套环境。

依赖的隐性升级会改变行为，让评测结果失去可比性。

**Example:** 提交 `uv.lock` 并固定基础镜像摘要，安装时启用哈希校验。

#### 信任与鉴权

在互联链路中验证对方身份，并校验签名时效与授权范围。

跨组织调用必须解决身份问题，否则无法追责。

**Example:** 请求体带签名与时间戳，接收方校验并拒绝过期报文。

#### 假设性文档检索

先让模型生成一段假设性答案，用它作为查询去检索真实文档。

它对短查询效果明显，代价是多一次模型调用。

**Example:** 先推断某错误码的含义并生成说明文本，再用该文本做检索查询。

#### 全局与局部检索

全局检索面向主题与社区概览，局部检索针对具体实体及其邻居。

提问类型不同，用错通道会答非所问。

**Example:** 问"整体风险分布"走社区级全局检索，问"某公司处罚记录"走实体级局部检索。

#### 关系抽取流程

在已确定实体之间判定并抽出有类型、有方向的关系及置信度。

关系质量决定多跳查询能否真正走通。

**Example:** 每条关系打上置信度分数，低于阈值的进入人工复核队列。

#### 关系权重设计

为关系设定强度系数或时间衰减，用于排序与剪枝。

它让高置信度、新近的关系优先被检索到。

**Example:** 权重取置信度乘时间衰减，一年后自动衰减到 0.4。

#### 内容审核机制

在生成与发布两端做敏感与违规内容检查并拦截。

合规风险一旦扩散，代价远高于拦截成本。

**Example:** 生成后送审，命中违禁词或画面风险则不入库并记录原因。

#### 内部API转MCP

把既有的 HTTP 或 RPC 接口批量包装成 MCP 工具。

存量系统众多时，这是复用现有能力的最低成本路径。

**Example:** 用一份清单驱动生成三十个查询工具的包装，逐个补齐描述与参数校验。

#### 冲突事实处理

面对同一属性的多个来源，按可信度与时效定夺并记录理由。

不做裁决规则就会随机给出互相矛盾的答案。

**Example:** 同一营收数字冲突时按来源等级与更新时选取，并写入裁决日志。

#### 冲突裁决机制

当多个 Agent 结论不一致时，按优先级或投票决定取舍。

没有裁决规则，冲突会演变成无休止的争论。

**Example:** 数值类结论以计算结果为准，描述类结论以证据条数多者为准。

#### 函数调用基础

让模型输出调用意图，由运行时执行对应函数并把结果回填进对话。

这是模型从"会说"变成"会做"的分界点。

**Example:** 模型给出 `get_weather(city)`，执行后把"18℃ 晴"作为一条工具消息追加。

#### 分区与压缩策略

按查询维度分区并选择压缩编码，以降低扫描量与存储成本。

小文件过多会让查询性能急剧下降。

**Example:** 按天分区配合 ZSTD 压缩，并定期合并小文件到目标大小。

#### 医疗问答图谱实战

围绕药品、疾病与禁忌关系建图，用于约束用药类回答。

错误信息后果严重，必须提供可核查的依据链。

**Example:** 查询两药能否同服，沿禁忌关系返回依据并标注证据等级。

#### 协议演进跟踪

关注协议版本变更，并评估其对本系统实现的影响。

忽略版本变化会在对方升级后突然全面失败。

**Example:** 订阅协议仓库的变更通知，评估是否需要同步改造适配层。

#### 协议选型对照

从接入成本、生态支持与治理能力对比不同互联协议。

避免为了追新而引入维护成本极高的方案。

**Example:** 内部单一生态用函数调用即可，跨团队复用选 MCP。

#### 压测方法

用接近真实的请求分布施加负载，观测吞吐、延迟与错误率。

不压测就无法确定容量上限与真正的瓶颈位置。

**Example:** 按线上比例构造长短混合流量，逐步加压找出系统拐点。

#### 反思修正循环

让 Agent 对自身产出做检查，并依据反馈重做一轮。

引入独立判据能降低遗漏，但循环次数必须设上限。

**Example:** 每轮只输出未解决问题清单，清单为空即结束。

#### 取数权限管控

限制谁能查询哪些表、哪些列与哪些行范围。

Agent 自动取数会显著放大越权风险。

**Example:** 为角色绑定可见列清单，敏感字段在查询层直接裁剪。

#### 召回率与准确率

召回率衡量该找到的内容是否被找到，准确率衡量返回内容中真正相关的比例。

两者互相制约，只调一个必然把另一个做坏。

**Example:** TopK 从 5 升到 20，召回率从 0.72 升到 0.91，准确率却从 0.65 掉到 0.38。

#### 可靠性复盘模板

用统一格式记录故障时间线、根因、影响范围与改进项。

格式统一才能横向对比，也能追踪改进是否真正落实。

**Example:** 每次事故补齐发现方式、止损手段、待改进项与负责人。

#### 可靠性成熟度模型

用分级标准评估团队在可观测、恢复与演练上的成熟水平。

它给改进提供可量化的目标位置。

**Example:** 当前处于二级，目标是三个月内达到关键故障可自动降级的四级。

#### 后端分页与缓存

用游标或偏移分页限制单次返回量，用缓存降低重复查询的计算成本。

结果集扩大后，列表接口与检索结果都必须分页，否则响应体与延迟都会失控。

**Example:** 检索结果按相关性取前五十条并用游标翻页，热门查询缓存六十秒。

#### 后端成本估算

按存储占用、请求量与出网流量估算数据库与服务的月度开销。

选型阶段需要可比的成本数字而不是模糊感觉。

**Example:** 按百万次订阅与亿级读操作估算成本，与独立向量库方案横向对比。

#### 向量库基础操作

用集合组织向量及其元数据，支持写入、删除与近似最近邻查询。

索引参数与元数据过滤能力决定线上性能与可用性的上限。

**Example:** `collection.upsert` 写入向量，`collection.query` 带 top_k 执行检索。

#### 向量扩展pgvector

在关系库中加装向量类型与相似度索引，实现一体化存储。

中小规模场景可省掉一套独立向量库，明显降低运维成本。

**Example:** 建扩展后按向量距离建立 HNSW 索引，并支持元数据过滤。

#### 告警阈值配置

依据历史基线波动设定分级告警线与静默规则。

阈值太松发现太晚，太紧则被噪声淹没。

**Example:** 以过去七天 P95 为基线，超过一点五倍并持续五分钟才触发告警。

#### 回归评测流水线

在代码与提示词变更后自动跑全量评测并与基线对比。

它能防止修好一处又坏掉一处。

**Example:** 流水线自动对比新旧版本分数，指标下降超阈值即标记失败。

#### 图片内容检索

为图片生成结构化描述或抽视觉特征，再纳入同一检索通道。

多模态资料无法只靠文字索引被找到。

**Example:** 用视觉模型为每张流程截图生成描述，与文件名拼接后入库。

#### 图谱与向量融合

同一份内容既存为图谱三元组也存为向量，检索时互为补充。

图擅长精确关系，向量擅长语义近似，两者不可互相替代。

**Example:** 节点属性文本入库为向量，关系另存三元组，关系类问题走图查询。

#### 图谱冷启动

在缺少历史数据时，用规则、公开数据与人工种子快速起量。

没有首批实体就没法开始建图，先做到七成再补三成。

**Example:** 用监管公示名单先建公司骨架，再逐步接入研报抽取。

#### 图谱可视化排查

用图浏览器查看子结构，直观定位缺失边、错误边与孤立节点。

抽象查询语句很难解释，图上看一眼就能发现异常。

**Example:** 某产品没有上游依赖，在浏览器里发现抽取阶段漏了一条关系。

#### 图谱增量更新

按事件流或批次只更新变化的三元组，并保留历史版本。

图谱构建成本高，整体重建代价难以承受。

**Example:** 接入公告解析的增量事件，用 MERGE 写入新三元组，旧关系标记失效。

#### 图谱建模基础

确定节点类型、关系类型与属性，并定义标识与约束。

建模一旦返工，后续抽取与查询都要重做。

**Example:** 金融研报图谱设公司、指标、报告三类节点与披露、属于两类关系。

#### 图谱权限隔离

按租户与角色切分子图，在查询入口限制可见节点范围。

图上的关系极易造成跨租户信息泄漏。

**Example:** 每条三元组带租户标签，查询入口注入过滤，未授权节点不可见。

#### 图谱演进路线

规划从单一场景子图到全域图谱的阶段目标与扩展路径。

避免一开始就追求全域覆盖而迟迟无法落地。

**Example:** 三阶段依次走通单行业实体抽取、多跳问答与跨行业融合。

#### 图谱质量评估

用覆盖率、一致性与三元组准确率衡量图谱的可信程度。

图谱质量问题常被误判为模型能力问题。

**Example:** 抽检两百条三元组，准确率 0.87，核心实体覆盖率 0.93。

#### 图谱运营成本

统计存储占用、写入吞吐与查询耗时，并据此确定容量。

图规模增长快，成本估算不准会直接卡住立项。

**Example:** 千万级三元组约占 40GB、查询 P95 约 300ms，据此规划三节点集群。

#### 增量索引更新

只对发生变化的文档做删除与重建，避免每次全量重新计算。

知识更新频繁时，全量重建的算力与时间成本都无法接受。

**Example:** 按内容哈希比对，只重切重嵌变化文件，放在夜间批处理中执行。

#### 复盘文档模板

统一项目复盘的框架，含目标、过程、问题与改进四部分。

结构统一才能横向比较并沉淀经验。

**Example:** 模板固定五节，其中"当时为什么这么选"为必填项。

#### 多智能体编排总览

规划多个 Agent 之间的分工、通信方式与终止条件等协作结构。

多 Agent 是手段而非目的，要先确认单 Agent 确实解决不了。

**Example:** 把检索、核验、成文分给三个角色，并明确总轮次上限与退出条件。

#### 多模型路由策略

按任务难度、成本与可用性把请求分派到不同模型。

让贵的模型只出现在真正需要的环节。

**Example:** 简单改写走小模型，失败两次或难度高时才升级到大模型。

#### 多模态上线清单

上线前核对审核、授权、成本、监控与降级方案。

多模态链路很长，任一环缺失都可能造成事故。

**Example:** 清单含审核覆盖率、授权凭证、失败率阈值与降级为静默出图的方案。

#### 多模态评测方法

分模态评估生成质量，如画面一致性、语音清晰度与字幕准确率。

多模态缺陷往往在单模态指标上看不出来。

**Example:** 用同一脚本对比两家服务，评估角色一致性与口型偏差。

#### 多跳推理查询

用两段以上关系连接推导答案，需要支持变长路径的图查询。

这是图谱相对纯向量检索的核心增量能力。

**Example:** 查询某公司实控人的公司参与过哪些并购，需沿控股与参股走两跳。

#### 多轮检索对话

在追问场景中先做指代消解与查询改写，再执行新一轮检索。

第二轮的查询质量直接决定指代类追问能否命中。

**Example:** 用户问"它的申请周期呢"，先还原为具体对象的申请周期再检索。

#### 失败案例归因

按解析、切分、召回、排序、生成、引用六类把失败问题归类。

归因错了，优化就会打在完全无关的环节上。

**Example:** 报错"没找到退款政策"，查日志发现是解析阶段漏掉了附件页。

#### 失败重试策略

子任务失败时按可恢复性决定重试、降级还是终止。

它与单次调用重试不同，关系到整个协作流程的走向。

**Example:** 外部接口失败重试两次，内部逻辑错误直接终止并保留现场。

#### 失败重试补偿

为失败任务设计自动重跑、人工介入与产物回收机制。

批量流水线必然有零星失败，不能全靠人工重来。

**Example:** 失败任务入补偿队列并换种子重试，仍失败则通知人工处理。

#### 子图检索策略

以种子节点为起点，按跳数、类型与权重扩张出有限规模的子图。

不加约束的全图遍历会让查询失控。

**Example:** 两跳扩张时限定关系类型白名单，并按权重截断到五十个节点。

#### 字幕与配音合成

生成与画面对齐的字幕，并合成匹配人设的语音。

字幕错位与音画不同步会直接影响完播率。

**Example:** 先用时间戳对齐字幕，再按句长调整配音语速。

#### 定时与重试策略

为每个活动设定超时上限、重试次数与退避间隔等参数。

重试策略不当会放大上游压力，把偶发故障变成持续故障。

**Example:** 只对超时与限流重试并采用指数退避，参数错误直接失败。

#### 实体抽取流程

从文本中识别候选实体并归一化，去重后写入图谱。

实体是整张图的骨架，抽错会污染所有下游查询。

**Example:** 正则与模型混合抽取公司名，再用别名表统一到标准标识。

#### 实体消歧方法

判断同名实体是否指向同一对象，并挂接别名与外部标识。

消歧错误会连出完全错误的关系链，且难以察觉。

**Example:** 结合行业代码与注册地规则，把同名公司区分到两个不同主体。

#### 实时订阅推送

用变更流把数据库增量推送给前端或 Agent 运行时。

它用于状态驱动的界面与触发式流程。

**Example:** 任务状态表变更后推送事件，前端无需轮询即可更新。

#### 审稿人模式

由一个 Agent 产出初稿，另一个 Agent 依据明确标准挑错并要求修改。

把质量检查交给独立角色，通常比自我检查更有效。

**Example:** 审稿 Agent 只输出问题清单，写作 Agent 据清单修订，最多两轮。

#### 客服多智能体实战

用分工协作的 Agent 处理意图识别、查证、回复与转人工。

它展示了协作如何带来可测量的指标提升。

**Example:** 意图识别与政策查证分开后，误转人工率从百分之十二降到百分之六。

#### 客服问答实战

把高频客服问题做成带引用的问答助手，并保留转人工兜底。

高频且效果可量化，是典型的 RAG 落地场景。

**Example:** 退款、物流、发票三类问题命中率达 0.81，未命中时转人工并附检索关键词。

#### 容量规划

依据峰值需求推算所需算力、存储与费用余量。

规划不足会限流，规划过度则浪费预算。

**Example:** 按大促峰值并发与平均 token 长度推算 GPU 数量，并留三成余量。

#### 对话历史管理

在一轮会话内维护消息序列，并通过裁剪与摘要控制其长度。

它只管当前会话内的消息流，跨会话的记忆需另行设计，见长期记忆抽取。

**Example:** 保留最近六轮原文，更早的轮次压缩成一条摘要消息。

#### 对话轮次控制

设置单次协作的最大轮次、终止条件与超时上限。

没有上限的多 Agent 极易陷入重复循环并烧掉预算。

**Example:** 达到十二轮或耗时九十秒即停止，并返回当前最优结论。

#### 小实战写作规范

规定实战案例的写作结构、代码可运行性与验收方式。

它保证全书实战内容的难度与质量一致。

**Example:** 每个实战给出前置条件、可运行代码与预期输出。

#### 层级索引构建

为文档建立"文档—章节—段落"多粒度索引，检索时可选择层级。

它兼顾长文档的宽召回与段落的精确定位。

**Example:** 标题级摘要与正文块同时入库，命中标题后再取该章节全部块。

#### 工作流持久化

把执行历史写入服务端存储，使流程能在崩溃后恢复。

长流程中任何一步都可能失败，没有持久化就得从头重来。

**Example:** 服务重启后从历史事件重放到当前步骤继续执行。

#### 工具Schema设计

用 JSON Schema 描述工具入参、返回与错误，并写清语义边界。

描述写得含糊，模型就会反复猜错参数格式。

**Example:** 把日期参数注明为 ISO 8601 格式，并枚举允许的时间范围。

#### 工具可观测埋点

在工具入口与出口记录耗时、结果状态与调用来源。

Agent 出问题时，要能分清是模型决策错了还是工具慢或错。

**Example:** 每次调用写一条追踪记录，含工具名、耗时、错误码与输入摘要。

#### 工具市场选型

在公开生态中比较现成工具的覆盖度、维护状况与安全边界。

自研之前先确认是否已有更划算的现成方案。

**Example:** 选型时检查最后更新时间、权限需求与是否支持私有化部署。

#### 工具沙箱隔离

用容器或微型虚拟机把工具执行与宿主资源隔离开。

沙箱是工具安全链路的最后一道边界。

**Example:** 每次调用起独立容器，根文件系统只读挂载，出口网络按需放行。

#### 工具治理清单

对工具的上线要求做统一规定，涵盖描述、权限、审计与退役。

工具数量增长后，没有治理就会迅速失控。

**Example:** 清单要求每个工具有负责人、版本号、权限说明与弃用日期。

#### 工具版本管理

对工具接口做版本标注与兼容策略，避免上游变更打断调用方。

工具是被多方共享的依赖，一改就影响所有接入的 Agent。

**Example:** 新增入参字段保持向后兼容，破坏性变更发布新版本并保留旧版半年。

#### 工具绑定基础

把工具定义绑定到模型上，使模型只能看到并调用已注册的能力。

收窄动作空间是 Agent 行为稳定的前提。

**Example:** `llm.bind_tools([search_tool])` 之后模型只会返回这两个工具的调用意图。

#### 工具评测方法

用调用成功率与参数正确率等指标衡量工具对模型的可用性。

工具描述质量需要量化反馈，不能靠直觉修改。

**Example:** 在一百条用例上把参数正确率从 0.72 提到 0.93，成功率随之上升。

#### 工具超时熔断

单次调用超时即快速失败，并在持续失败时暂时停止调用该工具。

它与重试不同：重试应对偶发失败，熔断防止故障期间把上游彻底压垮。

**Example:** 连续十次超时后打开熔断器三十秒，期间直接返回工具暂不可用。

#### 工具鉴权机制

在客户端到服务端的链路上验证身份并校验授权范围。

工具往往直连数据库与内部接口，鉴权缺失等同于裸奔。

**Example:** 用令牌换取作用域，服务端按作用域限定可访问的表。

#### 工具链编排模式

约定多个工具按何种顺序组合、由谁决定下一步动作。

步骤确定的用代码编排，需要判断的交给模型决策。

**Example:** 先固定调用取数工具，再让模型在两个分析工具中选择其一。

#### 并发与限流控制

用信号量限制同时在途的请求数，并用令牌桶限制请求速率。

上游模型有速率上限，超发会触发限流乃至封禁。

**Example:** 用 `asyncio.Semaphore(20)` 限制并发，调用前每秒发放五个令牌。

#### 并行任务调度

把互不依赖的子任务并发派发执行，并在末尾汇总各自结果。

它能显著压缩总耗时，但需控制并发度与共享资源占用。

**Example:** 八个子主题分析并发发出，用信号量限制同时在途四个。

#### 幻觉抑制策略

用强制引用、无依据时拒答与答案校验等手段减少无据生成。

在合规与专业场景中，编造内容比承认不知道危害更大。

**Example:** 要求"若无支撑证据则回答资料中未提及"，并校验引用是否真实存在。

#### 延迟优化清单

逐项排查并消除首 token 与整体链路中的等待环节。

延迟直接决定用户是否继续使用。

**Example:** 清单包含模型切换、缓存命中、并行化与流式输出等可执行动作。

#### 延迟分段分析

把端到端耗时拆成检索、重排、首 token 与生成分段分别统计。

总延迟不变时，分段数据决定优化方向。

**Example:** 首字延迟中检索占比最高，于是改为缓存与并行召回。

#### 引用溯源展示

让回答带上来源片段标识与原文链接，便于人工核对。

可核查是 RAG 场景落地的前提，也能把人工反馈变成评测素材。

**Example:** 每句结论后附片段编号，前端渲染为可展开的原文出处。

#### 成本与用量监控

采集调用量、token 用量与费用，按服务、环节与租户维度归集。

Agent 的调用量会随迭代轮次放大，成本容易在无人察觉时失控。

**Example:** 按链路记录输入输出 token 与模型单价，日终汇总各租户的账单明细。

#### 成本分账

把调用成本按团队、项目或用户维度归集与结算。

没有分账就难以推动成本治理。

**Example:** 每个请求带上业务标签，网关按标签汇总月度账单。

#### 成本预算控制

为单次任务设定 token 与费用上限，超限即收敛输出或中止。

多 Agent 的调用量是相乘关系，必须设硬性上限。

**Example:** 单任务预算零点三美元，用到八成时强制进入总结阶段。

#### 批量生产调度

用队列与并发控制安排大批量生成任务的执行顺序。

外部服务有并发与配额限制，盲目并发会被限流。

**Example:** 按优先级入队，每分钟放行十条，遇到限流自动降速。

#### 报表Agent实战

由 Agent 串联取数、分析与图表生成，产出业务结论。

它的价值在于自动发现异常并给出解释，而非只出图。

**Example:** 每日产出销售简报，自动标注跌幅最大的区域并给出可能原因。

#### 持续学习清单

列出后续应跟进的技术主题、获取渠道与优先级。

它给出学完后的继续路径，避免知识断档。

**Example:** 清单按推理优化、评测体系与协议演进分组并标注优先级。

#### 指标口径管理

为每个业务指标记录唯一权威的计算定义与负责人。

口径不统一时，Agent 与人的结论会长期互相打架。

**Example:** 在指标目录中写明活跃用户的唯一定义并指定负责人。

#### 推理安全加固

对输入输出做校验过滤，并限制服务暴露面与资源用量。

开放推理端点容易被滥用或遭受提示注入。

**Example:** 关闭未使用的接口，限制单请求长度并设置速率上限。

#### 提示词工程基础

通过角色设定、任务说明与输出约束组织输入文本，稳定模型的行为表现。

同一模型换一套提示词，工具调用成功率可能相差一倍以上。

**Example:** 系统提示写明"只从给定 JSON 字段取值，缺失则填 null"，显著减少多余字段。

#### 提示词模板管理

把提示词抽成带变量的模板文件，统一管理变量、版本与注入风险。

提示词是代码资产，同样需要评审、灰度与回滚。

**Example:** 用 Jinja 模板存 YAML 并标注版本号，改动必须走 PR。

#### 搜索工具封装

把内外网搜索能力封装成返回结构化结果的工具。

搜索结果的质量直接决定 Agent 的事实来源可靠性。

**Example:** 统一返回标题、摘要、链接与发布日期四项，并过滤广告结果。

#### 故障演练方案

定期人为制造依赖故障，检验降级与恢复能力是否真实有效。

不演练的兜底策略只是文档上的承诺。

**Example:** 模拟向量库不可用，确认系统自动降级为纯提示回答并正常返回。

#### 故障转移机制

主模型不可用时自动切换到备用模型或降级方案。

外部提供方的故障是常态而不是例外。

**Example:** 主模型连续报错即切备用模型，并在响应中标注实际使用的模型。

#### 敏感信息脱敏

在入库与日志两侧识别并遮蔽手机号、身份证、密钥等敏感值。

一旦写入向量库或备份，就难以彻底清除。

**Example:** 入库前把手机号替换为占位符，输出侧再过滤一遍作为兜底。

#### 数字人集成

把数字人形象与语音链路结合，形成对外服务入口。

它适合需要固定形象与合规留痕的场景。

**Example:** 数字人驱动口型与表情，文本答案来自同一 RAG 服务。

#### 数据分析实战

由 Agent 串联取数、清洗、分析与图表产出的完整流程。

分析类任务的错误多出在口径而非代码。

**Example:** 分析 Agent 必须引用指标口径表中的定义才能使用某个指标。

#### 数据回填流程

用新逻辑重算历史分区，并保证重算期间读取不被打断。

新旧口径切换时，必须给出一致的历史数据。

**Example:** 按分区逐批回填，每批发布影子表供一致性校验。

#### 数据备份恢复

定期备份并验证可恢复性，设定恢复时间目标与恢复点目标。

没有演练过的备份等于没有备份。

**Example:** 每日全量加日志增量，每季度演练一次恢复到临时实例。

#### 数据库查询工具

以受控方式暴露查询能力，并严格限制可访问的数据范围。

直接把数据库连接交给 Agent 权限过大。

**Example:** 只暴露预置视图的只读查询工具，并把用户标识设为必填过滤参数。

#### 数据成本优化

从扫描量、存储量与作业数量三个方向压降开销。

湖仓成本的增长往往远快于业务量增长。

**Example:** 分区裁剪失效导致全表扫描，修正条件后费用大幅下降。

#### 数据表建模

设计表结构、主外键关系与索引以支撑业务读写。

模型缺少约束时，Agent 写坏数据后难以修复。

**Example:** 会话表加租户列与唯一约束，并对时间列建立索引。

#### 数据质量校验

用规则检查完整性、唯一性与取值范围，异常时阻断或告警。

脏数据进入模型层后，错误会被放大且难以回溯。

**Example:** 金额字段不得为空且须大于零，校验失败则任务不发布数据。

#### 数据迁移方案

设计双写、回填、校验与切换步骤，以安全地迁移数据。

大表迁移出错难以回退，必须分阶段且可中断。

**Example:** 先双写并按主键抽样比对，回填完成后灰度切换读路径。

#### 文件存储集成

把上传文件放入对象存储，数据库中只保存引用信息。

文件不进数据库，避免大对象拖慢事务与备份。

**Example:** 上传后只存桶名与对象键，下载时生成带时效的签名链接。

#### 文件操作工具

按目录白名单暴露受控的读取、写入与列目录等文件能力。

与代码执行工具组合时会显著放大风险面。

**Example:** 限制只能访问指定工作目录，禁止绝对路径与上级跳转。

#### 文档加载与切分

把 PDF、网页等载入为文本，并按语义边界切成可嵌入的片段。

切分粒度直接决定召回质量，是整条索引链路的地基。

**Example:** 用递归字符切分器按八百字、重叠一百五十字切分，并保留标题层级信息。

#### 文档解析与清洗

从 PDF 与扫描件中恢复正文结构，并剔除页眉页脚、页码与乱码。

解析质量的上限决定了整条检索链路效果的上限。

**Example:** 用 OCR 加版面分析还原双栏排版，再按位置过滤水印行。

#### 断点续跑机制

记录已完成步骤并在重启后跳过，从断点继续执行。

相比整体重跑，可省下大量重复的模型调用开销。

**Example:** 已完成的抽取步骤被跳过，只重跑失败之后的环节。

#### 日志与配置管理

用结构化日志记录运行过程，用配置来源管理分环境的可变参数。

排障与问题复现都依赖这两者留痕。

**Example:** 日志输出含 trace_id 的 JSON 行，配置从环境变量加载并带默认值。

#### 显存估算方法

按权重、KV 缓存与激活值三部分估算所需显存与并发上限。

它是容量规划的第一步，能避免上线即显存溢出。

**Example:** 按权重与缓存算出一张卡需 21GB，据此定卡数与最大并发。

#### 智能分块策略

按标题、句子与语义边界切分文档，而非按固定字符数硬切。

硬切容易把答案拦腰截断，使关键信息分散到两个块里。

**Example:** 以二级标题为块、段落为最小单位，超长段落再按句子边界切分。

#### 服务健康检查

提供探活接口，区分存活与就绪两种状态，供编排平台决定是否发流量。

模型加载耗时较长，就绪与存活必须分开，否则会在加载期就被打请求。

**Example:** 权重加载完成前就绪接口返回 503，存活接口直接返回 200。

#### 本地开发联调

在本地把模型调用换成模拟或录制响应，与前后端同步迭代。

避免每次调试提示词都消耗线上额度，也缩短反馈环路。

**Example:** 用 mock 模型返回固定工具调用意图，本地跑通整条链再换真实模型验证。

#### 权限过滤检索

在检索阶段按用户身份裁剪可见范围，使越权内容不进入候选集。

先召回后过滤会把不该看的内容暴露给模型与日志。

**Example:** 向量元数据带上租户标识，查询时用过滤条件前置收敛范围。

#### 查询改写技术

把原始提问改写成更适合检索的表述，并补充同义词与上下文化信息。

口语化提问常与文档措辞不一致，是召回失败的主要来源之一。

**Example:** 把"怎么退钱"改写为"退款流程 申请条件"后再送入检索。

#### 查询结果缓存

按查询与数据版本缓存结果，减少重复计算。

同样的报表问题常被反复提问，缓存价值明显。

**Example:** 缓存键含 SQL 指纹与分区快照版本，上游数据更新即失效。

#### 检索缓存优化

缓存检索结果或向量，降低重复查询的计算与向量库压力。

热门问法重复率高，属于低风险高收益的优化手段。

**Example:** 以"归一化查询加知识库版本"为键缓存结果，知识库更新时整体失效。

#### 检索网关封装

用统一服务对外提供检索接口，内部检索实现可替换。

上层应用不必随向量库选型变化而改造。

**Example:** `/retrieve` 路由到 pgvector 或 Qdrant，Agent 代码保持不变。

#### 模型API调用封装

把各家厂商 SDK 统一封装成内部调用接口，屏蔽协议与参数差异。

模型更换频繁，业务代码与厂商耦合会让切换成本高到不可接受。

**Example:** 内部 `chat(messages, model=...)` 按 provider 分发到不同 SDK，调用方不感知差异。

#### 模型选型对照表

按能力、成本、上下文长度与延迟横向对比候选模型的决策依据。

它把"用哪个模型"从口味之争变成有数据支撑的选择。

**Example:** 便宜档模型做查询改写，生成环节用高配模型，按环节分配预算。

#### 沙箱资源配额

限制单个沙箱的 CPU、内存、运行时长与出网范围。

失控的沙箱会拖垮整台宿主机器。

**Example:** 单次执行限两核一 GB 内存、三十秒运行时长，网络只放行白名单域名。

#### 混合检索排序

把图上检索与向量检索的结果合并打分后统一排序。

它决定最终送进上下文的那几段内容及其顺序。

**Example:** 图查询给出精确子图，向量给出语义片段，按重叠度加权合并后重排。

#### 混合检索架构

把稠密向量检索与稀疏关键词检索并联执行，再融合两侧得分。

在专有名词与编号类查询上，稀疏通道常常不可替代。

**Example:** 向量库召回语义相近片段，同时用 BM25 捞精确术语，两路合并去重。

#### 混合编排实战

在同一系统中同时使用确定性代码与模型自主决策。

把稳定性要求高的部分交给代码，灵活性要求高的交给模型。

**Example:** 取数与校验用固定代码，分析维度选择与成文交给模型决定。

#### 湖仓一体演进

逐步把分散的数据源与计算层收敛到统一存储与格式之上。

目标是减少同步链路与口径分裂带来的复杂度。

**Example:** 先把宽表迁到开放表格式，再让 BI 与 Agent 统一查同一张表。

#### 灰度与回滚

按比例逐步放量新版本，并保留快速切回旧版本的能力。

模型与提示词的影响面大，必须始终可退。

**Example:** 保留两套路由配置，异常时把权重切回旧版本一分钟内生效。

#### 灰度发布策略

按流量比例或用户标签把新检索策略逐步放量，并保留回退通道。

检索质量的下降往往只在真实流量分布下才暴露。

**Example:** 先给百分之五的内部用户启用新分块，观察引用命中与投诉量再逐档放量。

#### 热点追踪选品

监控平台趋势数据，据此挑选有需求的内容主题与商品。

选题错误会让后续所有制作投入白费。

**Example:** 抓取增速榜与评论高频诉求，筛出三个可用题材。

#### 版权与合规

明确素材授权、肖像使用与生成内容的使用边界。

商用场景常因素材授权不清而被迫下架。

**Example:** 只使用可商用授权的素材与人声，并保留授权凭证备查。

#### 环境变量安全管理

把密钥等敏感值在运行时注入，不写进代码库、配置模板与镜像层。

密钥泄漏是上线阶段最常见也最易被忽视的事故来源。

**Example:** 用密钥管理服务注入凭据，并在日志侧过滤掉密钥前缀。

#### 生成参数调优

调整步数、引导强度、分辨率与种子，平衡质量与耗时。

参数对结果影响很大，固定默认值往往不够用。

**Example:** 同一分镜扫二十个种子挑出最稳的三个，固化进工作流配置。

#### 生成成本核算

统计单条内容在生成、合成与存储三个环节的花费。

单价乘以条数之后才知道能否规模化。

**Example:** 一条一分钟成片的生成与合成合计成本明确，据此设定日产能上限。

#### 用户反馈闭环

收集点赞点踩与人工纠错，转成评测样本与新语料驱动迭代。

让线上真实问题持续进入优化闭环，而不是靠内部猜测。

**Example:** 把点踩的两百条问答归因后补进评测集，并补齐缺失的知识文档。

#### 用户画像记忆

维护关于用户身份的稳定属性、偏好与约束的记录。

它不同于事件型记忆，应当长期有效且允许用户查看与修改。

**Example:** 记录行业、职级与常用语言，输出前先校验与当前请求是否一致。

#### 电商带货实战

按商品卖点批量生成短视频，并做合规检查与效果归因。

既要保证效果，也必须守住平台规则。

**Example:** 按卖点模板批量生成三十条，发布后对比完播与点击转化。

#### 画质增强流程

用超分、降噪与色彩修复提升生成素材的清晰度。

生成式视频常见模糊与闪烁，需要后处理兜底。

**Example:** 逐帧超分后重编码，闪烁用相邻帧加权平均抑制。

#### 留资系统实战

实现线索收集、去重、分配与跟进记录的完整流程。

字段多且规则杂，适合作为 Agent 生成表单与流程的试验场。

**Example:** 手机号唯一索引防重复，线索按地区与行业规则分配给销售。

#### 知识保鲜机制

为文档设定有效期与责任人，到期提醒复核并重新入库。

过期的知识比缺失的知识危害更大，因为它是可信地给出错误答案。

**Example:** 制度文档带复核截止字段，到期前两周推送提醒并自动建待办。

#### 知识库运营指标

追踪文档数量、新鲜度、引用命中率与人工改写率等运营数据。

它能区分"检索没做好"与"知识本身缺失"这两类问题。

**Example:** 某类问题引用命中率低，追查发现对应文档半年未更新，属知识缺失。

#### 短剧流水线实战

把剧本、分镜、生成、配音与剪辑串成批量生产流水线。

批量生产的关键在于每一步都可重跑、可替换。

**Example:** 某个分镜失败只重跑该环节，其余成片不重做。

#### 短期记忆设计

保存会话级近期的结构化事件，并设定生命周期与淘汰规则。

它与长期记忆的区别在于只覆盖当前会话，不会跨会话生效。

**Example:** 保存最近十次工具调用与结果摘要，超出数量则滚动淘汰。

#### 研报写作实战

用资料收集、图表生成、撰写与审稿角色协作产出研报。

长文档产出的质量瓶颈在审稿而不在写作。

**Example:** 审稿 Agent 按数据须有出处、结论不外推两条规则逐段检查。

#### 社区发现算法

用 Louvain 等方法把高连通子图识别为社区，得到更高层的主题结构。

它为全局检索提供了"主题级"入口，缩小首轮搜索范围。

**Example:** 对股权关系图跑社区发现，得到若干产业社区供全局问题使用。

#### 租户隔离设计

在数据、缓存与存储各层按租户切分，防止跨租户可见。

一旦泄漏就是最高等级的安全事故。

**Example:** 所有查询强制带租户条件，缓存键前缀租户标识，存储路径分层。

#### 稠密与稀疏融合

用加权求和或倒数排名融合两路结果，产出统一的排序分数。

融合权重需要评测集调参，不存在通用最优值。

**Example:** 用归一化分数加权求和，并在网格搜索中找出权重组合。

#### 系统设计面试

训练容量估算、瓶颈判断与降级取舍的表达框架。

这是高级岗位面试的主要考察面。

**Example:** 按需求澄清、量化估算、接口、瓶颈、演进的顺序作答。

#### 结构化输出解析

用 JSON Schema 约束模型输出格式，再解析为字典或校验后的对象。

链式编排与工具调用都依赖输出可被程序解析。

**Example:** 定义 `ToolCall(name, arguments)` 结构，模型返回后直接做模型校验。

#### 结果汇总机制

定义由谁以何种格式合并各分支产出并做最终裁决。

汇总环节常成为一致性与总成本的瓶颈。

**Example:** 主 Agent 收到三份同模板结论，只做差异比对与最终成文。

#### 缓存语义层

缓存语义相近的请求结果，在保持一致的前提下提升命中率。

与精确缓存相比，相似命中能覆盖更多真实重复问法。

**Example:** 以问题向量近邻为键存储答案，命中前先校验知识库版本。

#### 编排可视化

把 Agent 与工具的调用关系画成图，便于排查与沟通。

多 Agent 系统一旦复杂，文字描述不足以支撑排查。

**Example:** 在追踪平台查看调用树，找出循环调用链上那条无用分支。

#### 编排验收标准

预先写明可量化的完成判据，如成功率、轮次与成本。

没有验收标准，协作效果无法验证也无法改进。

**Example:** 规定成功率不低于 0.85、平均轮次不超八次、单次成本不超零点三美元。

#### 群聊管理器

维护多 Agent 会话的发言顺序与发言权分配规则。

谁在什么时候说话，是协作效率的关键变量。

**Example:** 采用规划者点名单个执行者发言的顺序，避免全员同时抢答。

#### 联邦评测方法

各方在自己环境独立评测，再汇总为统一口径的结果。

模型与数据不能集中时，联邦评测是可行替代方案。

**Example:** 各方按同一评分表执行评测，只上传分数与脱敏样例。

#### 能力卡片设计

用结构化文档描述 Agent 的身份、能力、输入输出与限制。

卡片描述质量直接决定对方能否正确选型与委托。

**Example:** 卡片写明"仅处理中文财报，不支持跨币种换算"，避免误委托。

#### 能力发现机制

让 Agent 能列出对方提供的能力及其描述与调用方式。

没有发现机制，互联只能靠人工配置维护。

**Example:** 读取对方的能力卡片，按描述匹配任务后再发起委托。

#### 自媒体矩阵实战

用同一份素材在多平台多账号分发，并统一管理排期。

这里省掉的是重复制作成本。

**Example:** 一次生成竖版与横版两套规格，统一排期分发并回收数据。

#### 自我改进循环

通过评测反馈迭代提示、流程与工具，持续提升效果。

这是可落地的改进路径，与改动模型权重完全不同。

**Example:** 每轮取失败用例改提示并回归验证，一周内忠实度明显提升。

#### 自然语言转SQL

把自然语言问题翻译为可执行 SQL，并在受控环境中执行。

它让业务人员自助取数，但执行范围必须被限制。

**Example:** 只允许在只读副本执行，并强制加时间范围与行数上限。

#### 自进化理论导读

梳理模型自我改进与能力涌现的理论脉络与现实边界。

理解哪些可行、哪些不可行，可以避免盲目追逐概念。

**Example:** 区分"通过反馈优化流程"与"模型自主改写自身权重"两类主张。

#### 薪资谈判准备

整理市场行情、期望区间与谈判话术，避免临场被动。

避免临场随意报价而吃亏。

**Example:** 给出期望区间上下限与两个可交换的让步条件。

#### 行级安全策略

在数据库层按用户身份限制可见与可修改的行集合。

应用层过滤容易被遗漏，数据库层才是最后防线。

**Example:** 按租户标识匹配当前会话设置过滤，跨租户查询直接返回空。

#### 表格数据检索

从结构化表格中定位单元格或取数，而非把表格当作普通文本切块。

数值型问题用文本检索几乎必然算错或漏行。

**Example:** 行内携带表头与单位，元数据标明行列位置，按年份定位到具体单元格。

#### 规划者执行者模式

由规划 Agent 生成步骤计划，再由执行 Agent 逐步落实。

适合步骤可预先确定的流程，避免边做边想走偏。

**Example:** 规划者先输出步骤表，执行者每完成一步回报状态。

#### 角色分工设计

为每个 Agent 明确职责边界、可用工具与产出格式。

职责重叠会导致互相重复，甚至陷入无限讨论。

**Example:** 检索 Agent 只负责给出证据片段，写作 Agent 不允许调用检索工具。

#### 计费归属划分

约定跨 Agent 调用链上各方的成本分摊与结算口径。

跨组织场景下不先定口径，事后极易出现账单争议。

**Example:** 按 token 用量归属发起方，工具侧成本记在提供方账上。

#### 订单业务落库实战

把订单主数据与明细规范落到关系库，并约束状态流转。

多 Agent 写入同一批数据时，状态约束是防错底线。

**Example:** 用状态机约束只有已支付订单可发货，非法流转直接拒绝。

#### 认证与授权

区分登录身份验证与对具体资源的操作许可。

Agent 代用户操作时，权限不能被放大。

**Example:** 服务账号只持有必要的行级策略，代用户调用时透传原始身份。

#### 记忆检索策略

按相关性与时间衰减召回记忆，控制注入上下文的条数与长度。

记忆多了不筛选就成了噪声源，反而干扰当前意图。

**Example:** 取相似度前五条并按时效衰减打分，总长控制在三百字内。

#### 记忆遗忘机制

主动清理过时、低价值或与用户意愿冲突的记忆。

记忆只增不减会把错误偏好长期固化下来。

**Example:** 九十天未命中的记忆归档，用户明确要求删除时立即清除。

#### 评估集初建

汇集代表真实场景的问题与参考答案，作为度量效果的基准。

没有评估集，任何改动的好坏都只能靠感觉判断。

**Example:** 先攒五十条真实问答，人工标注期望答案与必须命中的关键点。

#### 评测集构建方法

通过线上日志采样、业务专家标注与对抗样本组合成评测集。

评测集的构成决定了指标能否反映真实痛点。

**Example:** 七成取自线上真实提问，两成由专家编写，一成是无答案诱导问题。

#### 评测集版本管理

为评测集打版本号并记录增删改，保持结果跨版本可比。

评测集一变，历史分数就失去对比意义。

**Example:** 每次新增用例升版本号，并在报告中标注对应版本。

#### 语音客服实战

构建可打断、可转人工的语音客服，并监控转化表现。

语音能提升接通与转化，但失败体验的损失更大。

**Example:** 识别置信度低时直接转人工，并记录转接原因供优化。

#### 语音工具调用

在语音回合中支持模型发起工具调用，并把结果播报出来。

它让语音助手从"能说"变成"能办事"。

**Example:** 用户询问明天日程，模型调用日历工具后直接播报结果。

#### 语音延迟优化

通过预取、并行化与流式输出压缩语音链路的端到端延迟。

等待超过两秒，用户就会觉得助手没有响应。

**Example:** 先流式输出首句，后台并行生成后续内容，降低感知延迟。

#### 语音打断处理

在用户说话时取消当前生成与播放，并切换到新输入。

不能被打断的语音助手会显得迟钝而机械。

**Example:** 检测到语音活动即取消当前合成请求，立即播放新内容。

#### 调度监控大盘

集中展示任务成功率、运行时长与积压情况的监控视图。

定时任务失败若无人发现，数据会静默过期。

**Example:** 大盘按作业分组展示连续失败次数与数据新鲜度。

#### 资产血缘追踪

记录数据表之间的上下游依赖关系与变更影响范围。

变更上游之前能据此评估波及哪些下游。

**Example:** 修改原始事件表后，系统列出受影响的五张表与相关任务。

#### 资源与提示模板

MCP 中以只读内容与可复用提示两类接口暴露的非工具能力。

长文档与标准提示不必伪装成工具暴露。

**Example:** 把术语表做成资源供客户端读取，把审核提示做成可复用模板。

#### 跨框架消息格式

定义不同 Agent 框架之间可无损转换的消息与结构化数据表示。

框架生态割裂时，格式不统一就只能靠字符串拼接传递。

**Example:** 用统一 JSON 表示消息、工具调用与结果，各框架各写一套适配器。

#### 跨组织协作

在组织边界之外完成受控的任务流转与数据交换。

它涉及合规与责任划分，是互联最难的落地环节。

**Example:** 只在约定字段范围内交换脱敏结果，不传输原始客户数据。

#### 跨轮记忆传递

把上一轮的中间结论与关键信息带入下一轮会话。

长任务分段执行时，不传递就会重复劳动。

**Example:** 把已确认的三条结论写入共享记忆，后续轮次直接引用不再重算。

#### 输出解析器进阶

在基础解析之上处理多段文本、嵌套结构与格式错误的纠正重试。

复杂结构往往需要分步生成再拼接，单次输出难以保证稳定。

**Example:** 先解析出字段列表，再对每项发起第二次调用补全描述。

#### 边缘函数集成

把轻量逻辑放到边缘运行时执行，让请求就近得到处理。

它适合鉴权、脱敏与缓存命中这类短链路逻辑。

**Example:** 在边缘校验令牌有效性并注入用户标识，减少回源调用。

#### 连续批处理原理

让多个请求分批进入 GPU 执行，并在某条完成时立即补入新请求。

相比静态批处理，吞吐可提升数倍。

**Example:** 请求完成一条就补一条，GPU 利用率从四成升到八成以上。

#### 递归自改进风险

评估系统在缺少外部校验时反复自我修改导致的失控与退化风险。

没有独立评判标准的自我改进可能越改越差。

**Example:** 先固定一批人工标注的护栏用例，再允许系统自动迭代。

#### 部署交付流水线

从代码提交到构建、测试、灰度上线的自动化链路。

它把发布从人工操作变成可重复、可追溯的过程。

**Example:** 提交触发构建与评测，通过后自动发布到预发环境。

#### 重排序策略

用交叉编码器对初筛出的候选集重新打分，只保留高分片段进入上下文。

把召回与排序解耦通常是这个链条上性价比最高的单点优化。

**Example:** 用 bge-reranker 对二十条候选打分，取前三名送入提示。

#### 量化选型

在精度损失与显存、吞吐收益之间选择合适的量化方案。

它直接决定自建推理的成本下限。

**Example:** 先对比 FP16 与 INT8 的精度损失与吞吐提升，再决定是否上 INT4。

#### 金融研报图谱实战

把研报中的公司、指标与事件建成图谱，支持关系型问答。

指标与公司的对应关系用纯文本检索很难稳定命中。

**Example:** 问"哪些公司毛利率连续三年下降"，从指标节点沿年份路径反查公司。

#### 错误码规范

统一工具返回的错误分类与码值，让调用方能区别对待。

可预期的错误应该能被 Agent 自行恢复，而不是一律抛出。

**Example:** 区分参数错误、无权限、超时与数据为空，分别对应重试、提示与兜底。

#### 错误重试与超时

为外部调用设定截止时间，并对可恢复错误做有限次带退避的重试。

单次失败不应升级为整条链路失败，但重试无法阻止持续故障，见工具超时熔断。

**Example:** 调用超时 30 秒，指数退避重试两次，仍失败则向上抛出明确错误。

#### 长任务拆分

把耗时过长的作业切成可独立完成的小段处理。

单段过长会让失败重来的代价过高。

**Example:** 十万条文档索引按千条一批处理，每批提交一次事务。

#### 长文档处理

针对超出单次窗口的资料做分批读取、跨批摘要与结果合并。

报告与合同类任务无法靠一次性塞入完成。

**Example:** 按章节分批送入，产出结构化摘要表，最后一次调用合并结论并保留页码。

#### 长期记忆抽取

从对话与工具结果中提炼可复用事实并写入长期存储，跨会话生效。

只保留原始对话无法在跨会话场景中找回有用信息。

**Example:** 从"我更喜欢中文表格"中抽出偏好条目，跨会话时优先采用。

#### 限流与配额

按调用方设定请求速率上限与周期内的总量配额上限。

它与熔断不同：限流是主动约束，防止多方互相挤占。

**Example:** 每租户每秒十次、每天十万次，超限直接返回明确错误。

#### 集成项目验收标准

明确综合项目在功能、性能与质量上的验收门槛。

综合项目是检验全书技能是否贯通的关键环节。

**Example:** 验收要求覆盖检索准确率、并发指标、监控面板与回退方案。

#### 面试高频题精讲

针对高频考题给出标准答案与常见追问要点。

覆盖高频题比覆盖冷僻题更有效。

**Example:** 为每题准备主答案与两个常见追问的应答要点。

#### 项目深挖应对

准备对所写项目每个设计决策的追问与依据。

简历上的每个数字都会被追问。

**Example:** 记录每项优化的基线值、实验过程与最终结论。

#### 飞书CLI提效

用命令行工具批量处理文档、多维表格与消息。

它把重复的协作操作从界面点击变成脚本。

**Example:** 脚本批量导出多维表格记录并回写状态字段。
