## 学习目标

学习者将追踪一次理赔委托的十二条状态事件，判定哪一条是必须丢弃的状态回退，并算出接受该回退后重复扣费金额；判定条件为所选序号为 6 且重复扣费为 4.5 分（3 次乘以 1.5 分）。

**Bloom 层级**：Analyze（分析）

## 规则要点

- **回退判定**：当前状态的序号大于事件状态的序号即判回退，必须丢弃并记审计日志。状态序号为 `created` 1 < `accepted` 2 < `running` 3 < `completed` 4。
- **幂等重复**：事件序号等于当前状态序号，返回首次结果且不执行。
- **超时判定**：用 `>=`——事件到达时刻 ≥ 超时阈值且状态非终态才判超时。因此首次 `completed`（780 ms）在阈值 ≤ 700 ms 时判超时，在阈值 ≥ 800 ms（卡片 P95 口径）判为准时。
- **计费**：核保规则按次计价 1.5 分。若接受该回退，核保规则被重新执行一遍，按次计价 1.5 分意味着多扣 1.5 分；本时间轴上回退被接受了三次（序号 6、8、10），**合计重复扣费 4.5 分**。正确实现下重复扣费为 0.0 分，核保规则只执行 1 次，扣费 1.5 分。

## 使用建议

1. 先在三道挑战题里写下预测：必须丢弃的回退序号、接受该回退后的重复扣费、延迟到达是否判超时。锁定前不显示标准答案。
2. 点“提交判定”，每题两次机会；答错会显示该题的判定规则推导与反馈文案。
3. 把 `deadline_ms` 从 500 拖到 5000，观察序号 5（首次 `completed`，780 ms）在哪个阈值下被判超时。
4. 点“聚焦回退”把 905–1120 毫秒那一簇回退与幂等重复事件放到眼前：12 条事件挤在 5.5 秒内，全景视图只画色块（每条事件画成 30 毫秒宽的标记块，只是为了看得见，不代表事件持续时间），视窗缩小到 2600 毫秒以内才显示序号标签。
5. 滚轮已禁用（避免劫持页面滚动），用“显示全部”“聚焦回退”“＋／－”按钮控制视图。
