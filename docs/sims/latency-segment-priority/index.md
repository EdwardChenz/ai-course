## 描述

九个延迟分段以瀑布形式串行累加，构成端到端 P50；右侧读数区实时显示合计值、P95 与对 3.00 秒门禁的余量。学习者可点"套用"把某个动作的目标值直接写进滑块，也可以手工拖动。三道挑战题的答案一律按默认口径计算，与滑块当前值无关。

- **端到端 P50** = 九个分段当前值之和，实时更新
- **可省毫秒数** = 分段默认值 − 该动作目标值，为固定常数，不随学习者调节而改变
- **门禁** = P95 ≤ 3.00 秒为通过，等于 3.00 秒按通过计

## 学习目标

学习者将调节九个延迟分段的值并观察端到端 P50 的实时变化，在三个候选优化动作中按可省毫秒数排出收益顺序，并在三步全做后判定是否通过 3.00 秒的 P95 门禁；判定条件是排序为工具调用并行化、提示缓存、跳过查询改写，且判定结果为通过。

**Bloom 层级**：Evaluate（权衡）

## 使用建议

1. 先把"工具调用"从 630 毫秒拖到 230 毫秒，观察读数从 2,800 掉到 2,400 毫秒，其他分段不动。
2. 再把"首 token 等待"拖到 100 毫秒，观察读数大幅下移，随后意识到该段的可压缩下限受提示缓存命中率约束。
3. 三道题每题两次机会，提交后立即揭晓。注意第 1 题与第 2 题的答案刻意相反。

## 常见误解

- 占比最大的段落一定是该优化的段落（收益第一的是只占 22.5% 的工具调用）
- 工具调用并行化会改变 token 消耗从而影响成本
- P50 达标就等于 P95 达标
