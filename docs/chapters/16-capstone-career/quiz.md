# 测验：综合项目与求职准备

检验本章 10 个概念的掌握情况。先作答，再展开答案。

---

#### 1. 每个小实战必须交付的四件是什么？仓库结构为什么固定？

<div class="upper-alpha" markdown>

1. 可运行的仓库、可读的说明、可复现的复盘、可演示的脚本；仓库结构固定为 `app/`、`tests/`、`prompts/`、`evals/`、`README.md`、`retrospective.md`，这样各章的东西可以横向堆叠，合成项目时直接聚合
2. 上述四件之外还必须配一套 CI 与线上部署，否则不算交付
3. 只需仓库与说明两份，复盘与演示脚本属于加分项
4. 交付物由每章作者自行约定，只要能跑就行

</div>

??? question "查看答案"
    正确答案是 **A**。小实战的价值在于覆盖面而不是深度，一章一个、章章有，才可能串成后面的集成项目。说明里还有三条硬要求：写明运行环境与依赖版本来源（不写"最新版"）、写明一条从零跑起来的命令以及它成功时的输出长什么样、写明当前已知的三条局限。选 B 是把交付标准抬到了整本书之外，选 C 和 D 则放弃了横向堆叠的可能。

    **考查概念：** 小实战写作规范

    **参见：** [章节首页](../16-capstone-career/index.md)

#### 2. 复盘模板的六段里哪两段是真正的产出？第四段该怎么处理？

<div class="upper-alpha" markdown>

1. 六段各占同等篇幅，先后顺序可以自由调整
2. 第四段的指标对比可以先填示例数字，交付前再替换
3. 六段里第三段（方案）与第五段（踩坑）是复盘的真正产出，其余四段只是上下文；第四段的指标对比必须留空重填而不是复制示例数字
4. 复盘的价值在于完整记录"这次做了什么"，越详细越好

</div>

??? question "查看答案"
    正确答案是 **C**。复盘的价值在于留下"下次能用的判断"，而不是记录"这次做了什么"。选 B 的说法"没有真实数字的复盘在面试里一问就穿，这比没有复盘更糟"正是本章反复强调的那句——指标对比一栏宁可空着，也不能用示例数字占位。选 D 正好把复盘写成了工作日志。

    **考查概念：** 复盘文档模板

    **参见：** [章节首页](../16-capstone-career/index.md)

#### 3. STAR 讲述稿四段的长度占比与写法要求是什么？

<div class="upper-alpha" markdown>

1. 情境 15%、任务 15%、行动 50%、结果 20%；行动段每条改动都配一个被否掉的替代方案，结果段要给指标前后对比、门禁口径以及仍然存在的缺口
2. 四段各占 25%，不要偏重任何一段
3. 情境 50%、任务 20%、行动 20%、结果 10%
4. 情境要写行业大趋势与公司背景，行动要罗列用到的技术

</div>

??? question "查看答案"
    正确答案是 **A**。多数人把 STAR 写成一段流水账，结果每段都说不清——情境写成行业趋势、行动写成技术名词清单，正是最常见的两种写法。行动段占一半篇幅是因为它是唯一能证明"你真的做过"的部分，而被否掉的方案与理由恰恰是区分"做过选择"和"跟着做"的分水岭。

    **考查概念：** 作品集讲述稿

    **参见：** [章节首页](../16-capstone-career/index.md)

#### 4. 面试题应该怎么准备？"面试高频题精讲"这一节的结论是什么？

<div class="upper-alpha" markdown>

1. 题目会变、考的是原理不是题库，所以背标准答案是最有效的准备方式
2. 六类题各准备一个原理定义即可，不需要准备实测数字
3. 准备动作就是收集尽可能多的同类题库题目
4. 题目会变、考的是原理不是题库；六类题各准备一页纸，包含一个原理定义、一个你实测过的数字、一个你被否掉的方案

</div>

??? question "查看答案"
    正确答案是 **D**。三样齐了，这类题你怎么问都答得动。选 A 直接把章节的立论反了过来——背标准答案是最没用的准备方式，因为面试官改一个约束条件答案就作废。选 B 少了后两样，恰好是深挖时最常被追问的两样；选 C 则用题量代替了对原理的理解。

    **考查概念：** 面试高频题精讲

    **参见：** [章节首页](../16-capstone-career/index.md)

#### 5. 按四维各 0 到 3 分给"数据分析 Agent"那段讲述稿打分：它的情境、任务、行动都扎实，结果段只给了总耗时从 82 秒降到 31 秒、没给门禁口径也没提仍未解决的部分。它的标准总分、最弱维度与判定结论是什么？

<div class="upper-alpha" markdown>

1. 12 分，无最弱维度，可直接进作品集
2. 10 分，最弱维度是结果（1 分），判"补一项即可"
3. 8 分，最弱维度是行动（2 分），判"补一项即可"
4. 10 分，最弱维度是情境（2 分），判"补一项即可"

</div>

??? question "查看答案"
    正确答案是 **B**。达标规则是总分大于等于 9 判"直接进作品集"、7 到 8 判"补一项即可"、6 及以下判"重写"，所以 10 分仍需补一项。这一题的教训是：行动维拿满 3 分也救不了结果维的短板，追问"这 31 秒对应哪条 SLO"答不上来就散架。补上门禁口径与至少一条未解决的缺口，这一稿就能进作品集。

    **考查概念：** 作品集讲述稿

    **参见：** [章节首页](../16-capstone-career/index.md)

#### 6. 系统设计面试的七步框架是什么？被问到没准备过的部分怎么答？

<div class="upper-alpha" markdown>

1. 七步是需求澄清、数据层、检索层、编排、可靠性、成本、监控；遇到没准备过的部分，标准答法是"我现在的判断是这样，我会先量哪个指标来验证，验证不通过我会退回哪一步"
2. 七步是需求、数据、模型、部署、运维；顺序可以按面试官关注点自由调整
3. 遇到没准备过的部分应硬答一个看似完整的方案，避免现场卡壳
4. 标准答法是三句：判断是什么、先量哪个指标验证、验证不通过退回哪一步

</div>

??? question "查看答案"
    正确答案是 **A**。七步按顺序走完再回头补细节，面试官不会觉得你在绕；第一步"先问后答"尤其关键，不问就画图，画出来的必然不是你想要的东西。选 C 的三句虽然对了，但顺序上把它当成了独立技巧，忽略了它必须挂在七步框架之后使用。选 B 是硬答：暴露一个没想清楚的问题，比坦率说"这块我需要量一下"扣分更多。

    **考查概念：** 系统设计面试

    **参见：** [章节首页](../16-capstone-career/index.md)

#### 7. 薪资谈判的三条报数纪律是什么？为什么要强调"数字必须有出处"？

<div class="upper-alpha" markdown>

1. 报数应给单点数字，显得更自信
2. 过早报价会让你成为锚定，所以要尽早报价抢占锚点
3. 数字不必有出处，谈判里关键是态度
4. 报数三条纪律是给区间不给单点、先问区间再报数、数字必须有出处——同一个 0.89 可能是 200 题评测集上的分，也可能是 3 道题手测的结果，口径被追问一次数字就贬值一半

</div>

??? question "查看答案"
    正确答案是 **D**。谈薪的实质是用可核对的数据换对方的确定性，所以谈之前必须先把三类数据取到：岗位职责的市场区间、自身可量化成果、对方的预算结构。选 B 把纪律说反了——过早报价会让你成为锚点，先问区间才是拿主动权。选 C 忽略了一个便宜的准备动作：谈之前把每个数字的样本量与判定方式记在纸上。

    **考查概念：** 薪资谈判准备

    **参见：** [章节首页](../16-capstone-career/index.md)

#### 8. 项目二的"完整报告生成"这一项，延迟门禁该怎么定？验收纪律有哪三条？

<div class="upper-alpha" markdown>

1. 也要按交互式的 3.00 秒门禁判定，否则与项目一不一致
2. 交互式部分仍用原四条阈值，但长报告生成按异步口径单定 P95 小于等于 120 秒；豁免必须有失效日期与处置手册链接且同时存活不超过 1 条，指认不了评测集版本或采样口径的数字按缺失处理、缺失按不达标
3. 长报告生成不设延迟门禁，只看数字正确率即可
4. 阈值应为本项目单独新建一份 `quality-gate.yaml`，不必与第十一章共用

</div>

??? question "查看答案"
    正确答案是 **B**。把长报告挪到异步口径，正是第十一章"被测对象变了尺子就要重定"的同一原则。选 A 的错误在于把同一条阈值套到两个被测对象上，验收必然出现"报告生成永远超时"的荒谬判定。选 D 同样违背本节的第一条纪律——阈值要写在与第十一章同一份配置文件里，改一处两处同时生效。

    **考查概念：** 集成项目验收标准

    **参见：** [章节首页](../16-capstone-career/index.md)

#### 9. 项目深挖的四类问题分别考什么？哪些回答是危险信号？应对法是什么？

<div class="upper-alpha" markdown>

1. 深挖只需要把 STAR 四段背熟，四类问题都从这四段里找答案
2. 数字只要准确就行，不必准备它的算法与样本量
3. 四类是"为什么这么做""替代方案""失败过什么""数字怎么来的"；只说"业界都这么做"、说不出任何被否方案、只有成功案例、数字来自个人印象都是危险信号；应对法是 STAR-QA，把追问提前写进讲述稿
4. 深挖应该临场发挥，事先写好答案反而会让回答显得不自然

</div>

??? question "查看答案"
    正确答案是 **C**。深挖的本质是验证你是不是真的做过，四类问题各配一种回答材料：决策依据加当时的约束条件、至少一个被否方案加否掉它的判据、一次改错方向的经历、指标定义与样本量与门禁口径。选 D 的顾虑恰好说反了——**把追问提前写进讲述稿**，面试时就不会因为答不上来而卡住整段；问之前先自问一遍，比被问到现场卡壳强。

    **考查概念：** 项目深挖应对

    **参见：** [章节首页](../16-capstone-career/index.md)

#### 10. 一对一辅导的三条纪律是什么？为什么"会后当天落待办"这条不能省？

<div class="upper-alpha" markdown>

1. 议题越多越好，一次会话尽量多覆盖几个方向
2. 议题不超过三个、事前把假设写出来而不是等对方给答案、会后当天把结论落成待办；少了第三条，辅导就退化成聊天
3. 会后把结论整理成文档即可，不必当天落成待办
4. 事前不必写假设，直接听对方给答案效率更高

</div>

??? question "查看答案"
    正确答案是 **B**。一次有效会话按议题推进，事前准备比会话时长更重要——辅导的价值随你的提问质量变化，而提问质量来自你事先想清楚的东西。选 D 等于把辅导变成听课：事前没有假设，对方给你的只能是通用建议。选 C 缺了最关键的一条，会后不落待办就意味着下次会话又要从零开始。

    **考查概念：** 一对一辅导规划

    **参见：** [章节首页](../16-capstone-career/index.md)
